# Décisions techniques

Ambiguïtés mineures tranchées en cours de route (option la plus sûre et la plus simple).
Le cahier des charges (`docs/CAHIER_DES_CHARGES.md`) prévaut en cas de conflit.

## Phase 1 — Squelette

| #   | Décision                                                                                                                                                   | Raison                                                                                                                                                                                                                    |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | L'interface est servie par un protocole privilégié `app://renderer` (et non `file://`).                                                                    | Permet une CSP en en-tête HTTP, une origine stable pour l'IPC et le blocage de `file://`.                                                                                                                                 |
| D2  | `originOf()` reconstruit l'origine `app://renderer` à la main.                                                                                             | L'URL de Node renvoie `"null"` comme origine d'un schéma non spécial : sans cela, tous les appels IPC de l'application installée étaient refusés. Une URL sans hôte (`file:`, `data:`) n'a jamais d'origine de confiance. |
| D3  | CSP : `style-src 'self' 'unsafe-inline'`, `script-src 'self'` strict.                                                                                      | Radix injecte des balises `<style>` (verrouillage du défilement des fenêtres modales). Aucun script en ligne n'est permis en production.                                                                                  |
| D4  | En dev seulement, le WebSocket du serveur Vite (`ws://localhost:<port>`) est joignable. Les origines de navigation et d'IPC n'en font pas partie.          | Rechargement à chaud ; le code de production n'est pas concerné.                                                                                                                                                          |
| D5  | Les URL sont journalisées sans paramètres ni fragment, et sans contenu pour `data:`/`blob:`.                                                               | Aucun jeton ni donnée dans le journal (B.3).                                                                                                                                                                              |
| D6  | Les notifications (Radix Toast) passent sur Alt+N au lieu de F8.                                                                                           | F8 est réservé à la mise en attente en caisse (A.5) ; Radix l'interceptait sur toute la fenêtre.                                                                                                                          |
| D7  | Préférences d'affichage (thème, langue, taille du texte) dans un JSON du dossier utilisateur, hors de la base.                                             | Propres au poste, nécessaires avant le déverrouillage de la base chiffrée ; ce ne sont pas des données métier.                                                                                                            |
| D8  | `baseUrl` supprimé des tsconfig, chemins `paths` relatifs (`./src/...`).                                                                                   | Option dépréciée par TypeScript 6 (erreur TS5101).                                                                                                                                                                        |
| D9  | `rolldownOptions` au lieu de `rollupOptions` dans `electron.vite.config.ts`.                                                                               | Vite 8 utilise Rolldown ; `rollupOptions` est déprécié. electron-vite 6 lit `rolldownOptions`.                                                                                                                            |
| D10 | Trois projets TypeScript : `node` (main, preload, shared, tests unitaires hors interface), `web` (renderer et ses tests), `e2e` (Playwright, avec le DOM). | Chaque fichier est typé avec l'environnement où il s'exécute.                                                                                                                                                             |
| D11 | Config Vitest en `.mts`.                                                                                                                                   | Le chargeur de configuration natif de Vite refuse l'ESM dans un `.ts` chargé en CommonJS.                                                                                                                                 |
| D12 | Chargement asynchrone des écrans : `useEffect` + `.then()` avec garde `active`, nouvel essai par un compteur.                                              | Règle `react-hooks/set-state-in-effect` (pas de `setState` synchrone dans un effet).                                                                                                                                      |
| D13 | `npm audit` : 15 vulnérabilités **modérées**, toutes en dépendances de développement (`minimatch` via typescript-eslint), 0 en production. Acceptées.      | Pas de faille critique ; la seule correction proposée (`--force`) casserait la chaîne de lint. À revoir à chaque mise à jour de typescript-eslint.                                                                        |
| D14 | Les tests e2e tournent sur le build (`out/`) avec `BOUTIQUE_TEST_USER_DATA` (dossier temporaire), lu uniquement si l'application n'est pas empaquetée.     | Teste le vrai chemin de production (`app://`, sans DevTools) sans toucher aux données de l'utilisateur.                                                                                                                   |

## Phase 2 — Base chiffrée, authentification, rôles, audit

Décisions validées par le propriétaire : **D16** (bibliothèque Argon2) et **D17** (séquestre de la clé de la base).

| #   | Décision                                                                                                                                                                                                                                                                                                                                                               | Raison                                                                                                                                                                                                                                 |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D15 | SQLCipher v4 (`cipher = 'sqlcipher'`, `legacy = 4` : AES-256-CBC + HMAC-SHA512) avec une **clé brute** `x'…'` de 256 bits aléatoires.                                                                                                                                                                                                                                  | La clé est déjà aléatoire : la dérivation PBKDF2 n'apporte rien et coûtait 180 ms par ouverture (11 ms en clé brute). La clé n'apparaît que dans le PRAGMA, jamais dans un journal.                                                    |
| D16 | Argon2id par `@node-rs/argon2` 2.2.2 (64 Mio, 3 passes, 1 fil).                                                                                                                                                                                                                                                                                                        | L'Argon2 intégré à Node n'existe pas dans Electron (BoringSSL). Binaire N-API précompilé, sans script d'installation ni recompilation ; ~0,1 s par vérification.                                                                       |
| D17 | Séquestre de la clé de la base sous la clé de récupération : `boutique.key.recovery` (AES-256-GCM, clé dérivée par Argon2id, paramètres enregistrés dans le fichier).                                                                                                                                                                                                  | Sans lui, perdre le compte Windows ou le poste rendrait la base illisible (DPAPI lie la clé au compte). À inclure dans les sauvegardes (phase 8).                                                                                      |
| D18 | API asynchrone de `safeStorage` (`encryptStringAsync`, `decryptStringAsync`), avec renouvellement si `shouldReEncrypt`.                                                                                                                                                                                                                                                | L'API synchrone est dépréciée dans Electron 45 ; l'asynchrone reste adossée à DPAPI sous Windows et relit les données de l'ancienne.                                                                                                   |
| D19 | `audit_hash()` (SHA-256) est une fonction de l'application, exigée par le trigger d'insertion du journal.                                                                                                                                                                                                                                                              | Un outil tiers, même muni de la clé, ne peut pas écrire de ligne valide. Limite connue : supprimer les **dernières** lignes ne casse pas la chaîne ; un ancrage externe (empreinte de tête dans les sauvegardes) est prévu en phase 8. |
| D20 | Migrations écrites dans `db/templates` avec quelques macros (date ISO, booléen, Luhn, immuabilité), développées par `scripts/build-migrations.mjs` vers `db/migrations` (fichiers versionnés, embarqués dans le build). Un test vérifie que les deux correspondent.                                                                                                    | Le contrôle de Luhn en SQL pur fait ~1 500 caractères ; les macros évitent les fautes de recopie. Le script refuse de réécrire une migration existante sans `--force`.                                                                 |
| D21 | Catégories limitées à **trois niveaux** (famille › catégorie › sous-catégorie).                                                                                                                                                                                                                                                                                        | SQLite n'accepte pas de `WITH RECURSIVE` dans un trigger : l'héritage des attributs et l'absence de cycle ne sont vérifiables par la base qu'avec une profondeur bornée.                                                               |
| D22 | Plafond de crédit client à 0 par défaut : aucune vente à crédit tant que le gérant n'a pas fixé un plafond.                                                                                                                                                                                                                                                            | Option la plus sûre ; contrôlée par trigger à la validation de la vente.                                                                                                                                                               |
| D23 | Connexion PIN : identifiant + PIN de 4 à 8 chiffres (suites et répétitions refusées) ; la session n'a que `pos.use`, `product.view`, `stock.view`, `customer.manage` (dans la limite du rôle). L'utilisateur choisit son PIN après une connexion par mot de passe ; l'administrateur peut seulement le retirer.                                                        | « Code PIN limité aux droits de caisse » (B.1) ; pas de liste d'utilisateurs affichée avant connexion ; l'administrateur ne connaît pas les PIN.                                                                                       |
| D24 | Limitation : aucun délai avant 3 échecs, puis 5 s, 10 s, puis blocage 15 min, 30 min… jusqu'à 1 h ; compteurs séparés mot de passe / PIN ; récupération limitée à 5 essais par 15 min.                                                                                                                                                                                 | « Délai croissant puis verrouillage temporaire » (B.1), sans bloquer définitivement le seul administrateur.                                                                                                                            |
| D25 | Pas de mot de passe administrateur par défaut : l'assistant le fait choisir.                                                                                                                                                                                                                                                                                           | Satisfait « changement de mot de passe obligatoire au premier lancement » sans jamais exposer de secret par défaut. Les comptes créés ensuite reçoivent un mot de passe provisoire à changer.                                          |
| D26 | La clé de récupération est renouvelée après chaque récupération du compte administrateur.                                                                                                                                                                                                                                                                              | Une clé utilisée a pu être vue par un tiers.                                                                                                                                                                                           |
| D27 | `trusted_schema` laissé à sa valeur par défaut.                                                                                                                                                                                                                                                                                                                        | Avec `OFF`, SQLite refuse d'appeler `audit_hash()` depuis un trigger (better-sqlite3 ne marque pas les fonctions comme « innocuous »). Le schéma est chiffré et ne provient que de nos migrations.                                     |
| D28 | Adaptateur Zod maison pour React Hook Form (`src/renderer/lib/form.ts`) au lieu de `@hookform/resolvers`.                                                                                                                                                                                                                                                              | La version 6 du résolveur impose un arbre de dépendances optionnelles en conflit (effect, typeschema) ; nos formulaires sont à plat.                                                                                                   |
| D29 | Tables Utilisateurs et Journal d'audit en HTML simple (pagination de 50 pour l'audit).                                                                                                                                                                                                                                                                                 | Volumes faibles ; TanStack Table/Virtual arrive en phase 3 avec le catalogue (50 000 produits).                                                                                                                                        |
| D30 | Colonnes ajoutées à l'Annexe E : `users.pin_failed_attempts` / `pin_locked_until`, `customers.anonymized_at`, `goods_receipts.location_id`, `quote_lines.serial_unit_id`, `payments.installment_id`, `sale_returns.cash_session_id`, `warranty_claims.warranty_expired`, `inventory_sessions.location_id`, `categories.sort_order`, `tax_rates.is_active`.             | Nécessaires aux règles du cahier (blocage PIN, anonymisation B.3, stock multi-emplacements, réservation par devis, échéancier, remboursement en caisse, alerte de garantie) sans migration ultérieure.                                 |
| D31 | `sales.tax_total` n'est pas encore recoupé avec les lignes par la base.                                                                                                                                                                                                                                                                                                | Le mode de calcul (prix TTC ou HT, arrondis) sera fixé avec la caisse en phase 5, puis contrôlé par une nouvelle migration.                                                                                                            |
| D32 | Données dans `%APPDATA%/Boutique Gestion/donnees` (`boutique.db`, `boutique.key`, `boutique.key.recovery`, `sauvegardes/`). Une seule session à la fois.                                                                                                                                                                                                               | Application mono-poste ; dossier propre à l'utilisateur Windows (B.5 : accès limité au dossier de données).                                                                                                                            |
| D33 | `uuid` forcé en 11.1.1 sous `exceljs` (`overrides` du package.json).                                                                                                                                                                                                                                                                                                   | `exceljs` 4.4.0 tire une version d'`uuid` visée par GHSA-w5hq-g745-h8pq ; la 11.1.1 garde l'export CommonJS utilisé (`v4`). 0 faille en production.                                                                                    |
| D34 | Marques, catégories et caractéristiques modifiables avec `settings.manage` (administrateur) ; consultation avec `product.view`.                                                                                                                                                                                                                                        | Le cahier les réserve à l'administrateur (4.1, 4.12) ; aucune nouvelle permission n'est créée. Un gérant crée les produits avec les référentiels existants.                                                                            |
| D35 | Les IMEI et numéros de série s'enregistrent à la réception de marchandise (phase 4). La phase 3 livre leur affichage sur la fiche, la recherche (Ctrl+K) et leurs étiquettes.                                                                                                                                                                                          | Une unité doit naître avec son mouvement de stock d'entrée : la créer depuis le catalogue désynchroniserait unités et stock.                                                                                                           |
| D36 | Import du catalogue : création seulement (une référence existante est une erreur), tout ou rien, en deux temps (analyse simulée dans une transaction annulée, puis confirmation par jeton valable 15 min). Marques absentes créées seulement pour un administrateur. CSV au `;` ou à la `,` ; à l'export CSV, les cellules commençant par `= + - @` sont neutralisées. | Option la plus sûre : aucune modification de prix en masse non tracée ; l'utilisateur voit toutes les erreurs avec leur ligne avant d'écrire quoi que ce soit ; pas d'injection de formule dans un tableur.                            |
| D37 | Référence interne générée si vide (`P000042-1`) ; le coût moyen suit le prix d'achat saisi tant que la variante n'a aucun mouvement, puis seules les réceptions le recalculent.                                                                                                                                                                                        | Saisie rapide ; le coût moyen pondéré (4.3) reste la seule source après la première entrée.                                                                                                                                            |
| D38 | Le code d'une caractéristique est unique sur toute sa lignée (ancêtres et descendants), et sert de colonne `attr:code` à l'import/export.                                                                                                                                                                                                                              | Un produit ne voit jamais deux caractéristiques du même code ; l'import par colonnes reste sans ambiguïté.                                                                                                                             |
| D39 | Étiquettes : PDF (Code 128, planche A4 3 × 8 de 70 × 37 mm ou rouleau 50 × 30 mm) enregistré par le processus principal puis imprimé depuis la visionneuse. Polices PDF standard ; pdfmake n'a accès ni au réseau ni au disque.                                                                                                                                        | Pas d'imprimante d'étiquettes testable ici (limite connue) ; un PDF s'imprime sur toute imprimante. Le code-barres encode le code-barres fabricant, sinon la référence, ou le numéro de série pour une unité suivie.                   |
| D40 | Photos produit : PNG, JPEG ou WebP reconnus par leur signature, 2 Mo au maximum, copiées dans `donnees/images` et renvoyées à l'interface en `data:` (déjà permis par la CSP).                                                                                                                                                                                         | L'interface ne lit jamais le disque ; un faux fichier image est refusé.                                                                                                                                                                |
| D41 | Avertissement `react-hooks/incompatible-library` désactivé sur l'unique appel à `useReactTable`.                                                                                                                                                                                                                                                                       | Limite documentée de TanStack Table avec le compilateur React : le composant n'est simplement pas optimisé. Ce n'est pas une règle de sécurité.                                                                                        |
| D42 | Recherche produit : la lecture part des résultats FTS5 (`CROSS JOIN`), trie seulement les identifiants, puis lit le détail de la page.                                                                                                                                                                                                                                 | Un `v.id IN (MATCH)` était réévalué pour chaque variante (116 s sur 50 000) ; le tri complet avec le stock dépassait 100 ms. Mesuré sous 100 ms par test sur 50 000 produits.                                                          |
